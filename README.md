# 对戒配石台（hxyfront-62006）

面向珠宝镶嵌工作室的对戒配石前端：每张订单配两颗裸石，规则化判定配对是否成立。

## 配对规则

一张订单两颗裸石，必须同时满足：

1. **外形相同**；
2. **克拉差不超过 0.02**；
3. **色级差不超过一级**（D 最好、J 最差，即 |色级序号差| ≤ 1）。

挑石与拒绝：

- 按**克拉差最小优先**挑最优候选两颗（并列时按编号定序，保证结果稳定）；
- 最优候选**被别的订单占用**、克拉差超限或色级差超限，都**整次拒绝**——不挑下一颗，也不动任何已配对记录；
- **拆对**只释放本对两颗，其他订单配对不受影响；
- **换石**先把旧颗还原回池子，再拿“新颗 + 原伙伴”整体重验；占用、外形、克拉、色级任一项不过，就**保留原对**。

## 预置数据

- 14 颗裸石：圆形 6、椭圆 4、梨形 2、祖母绿切 2；
- 4 张订单，每单两颗：
  - ORD-01 林家对戒（圆形）、ORD-02 周家对戒（圆形）：按顺序配石可演示“最优候选被占用 → 整次拒绝”；
  - ORD-03 陈家对戒（椭圆）：最优候选色级差两级，整次拒绝；
  - ORD-04 赵家对戒（祖母绿切）：唯一一对合格。

## 文件结构

| 文件 | 职责 |
| --- | --- |
| `src/matching.ts` | 配对判定纯逻辑：候选挑选、自动配石、拆对、换石重验 |
| `src/storage.ts` | 浏览器存档（localStorage）、预置数据、读档容错 |
| `src/App.tsx` | 页面：订单卡、候选预览、配石/拆对/换石、裸石池 |

## 数据存储

数据只存浏览器 localStorage（键 `ring-pair-bench:v1`），刷新保留；页面上的“恢复出厂预置”可清空进度回到初始状态，不涉及任何服务器。

## 本地运行

```bash
npm install
npm run dev
```

技术栈：React 19 + Vite + TypeScript，开发端口 62006。
